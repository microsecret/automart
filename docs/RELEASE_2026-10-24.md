# Messages and favorites — 24 October 2026

## Scope

- Compact original phone/key scenery for messages, using the approved petrol,
  titanium and copper palette. The source illustration was generated earlier;
  optimized local WebP assets are 28,688 and 68,004 bytes. Headings and controls
  remain accessible HTML, not text baked into the illustration.
- Favorites has its own existing 3D heart illustration instead of repeating the
  car banner. Grid/list controls now have accessible names.
- Shared material avatars cover conversation lists, conversation headers,
  Telegram messages and seller/review identities in vehicle and part details.
- Message search runs across the authenticated owner's entire message history,
  counterpart names and listing titles before pagination. It presents the actual
  latest reply even when an older message matched.
- Search uses bound SQLite GLOB parameters with literal metacharacter escaping
  and one-character case pairs, including Cyrillic/Ё. Queries are normalized to
  NFC and limited to 120 characters. This is not a general Unicode case-folding
  engine or a full-text index. The unfiltered/unread paths stay separate.
- Debounced search and reset preserve input focus; clearing returns to page one.
  A 44px search control and explicit unread-counter styling improve readability.
- A bounded scrollable conversation list with sticky search prevents a full
  page of 20 conversations from stretching the empty right-hand preview.

## Verification

All builds and execution take place on the server. The authenticated audit uses
only a disposable `/tmp/automart-auth-audit.*/automart-audit.db` database and
fixture accounts; it does not impersonate real users or write production messages.

- `tests/conversation-search.test.mjs` and existing connection-policy tests:
  13 passing unit tests.
- TypeScript, scoped ESLint and optimized Next production build.
- `scripts/verify-message-workspace.mjs`: API/browser assertions covering
  a mailbox with 25 conversations,
  historical matches beyond page one, current last reply, case-insensitive
  Cyrillic names, listing titles, literal wildcard/SQL-looking input, pagination,
  length limit, denied anonymous/foreign access and unchanged unread state.
- Browser checks: desktop/mobile × light/dark, loaded original artwork,
  compact headers, focus/reset, unread text, no horizontal overflow, accessible
  favorites grid/list switching, runtime errors and screenshots.
- The first isolated test fixture omitted a listing subject and was rejected
  by the existing database constraint. The fixture now creates a complete car.
- One screenshot review led to a solid-fill messages action and larger explicit
  white unread counters; screenshots wait for the cleared search response.
  Full-mailbox screenshots also exposed the unbounded preview height; the
  bounded list is checked for overflow and keyboard access to lower rows.

Impeccable guided the bounded visual review and preservation of the approved
style. Kluster is not exposed by this session's tools; no Kluster verification
is claimed. No dependency, database schema or Telegram moderation policy changes
are included in this release. Production sign-in as a real user remains outside
the fixture-account checks.

Promotion must use the verified `.next-build` artifact, preserve the previous
build, and pass readiness (including database-backed catalog JSON) and the
production smoke audit. A healthy catalog point check is not proof that the
22 October SQLite incident's original retaining transaction was identified.
