# Frontend-аудит «Авторынка»

Дата: 2026-08-10
Основание: исходный код, production API, переданные скриншоты главной, каталога, категорий транспорта, запчастей, аукционов и личного кабинета, а также browser-smoke на desktop. Для проектирования использован переданный Frontend Design skill: спокойная и предметная визуальная иерархия вместо декоративного редизайна.

## Актуальный статус исправлений

Закрыты в коде и ожидают финальной серверной проверки релиза: глобальные error/not-found состояния, typed API fetcher, skeleton/empty/error для основных выдач, общая синхронизация избранного, загрузка фото транспорта, активная контекстная навигация, безопасные media fallback, зависимые фильтры и видимые focus/disabled состояния.

В текущем релизе дополнительно исправлены два наблюдавшихся UX-дефекта:

- фильтры запчастей больше не сжимаются в узкую колонку рядом с «Подбором по авто» — поиск занимает две колонки, остальные элементы остаются в читаемой трёхколоночной сетке;
- главная получила ненавязчивый «Маршрут сделки» из трёх реальных этапов. Это усиливает доверие без ещё одного декоративного баннера.

Ниже сохранены только реальные открытые риски и критерии их приёмки. Исторические пункты помечены как закрытые, чтобы документ не вводил команду в заблуждение.

## Critical

### C-01. Глобальные error/not-found состояния — закрыто в коде, ждёт server smoke

- **Исправлено:** добавлены локализованные recovery-экраны с повторной попыткой и безопасным возвратом в каталог.
- **Проверка релиза:** намеренно получить 404 и временную API-ошибку на production; убедиться, что данные формы не теряются.

## High

### H-01. API-ошибки в ключевых выдачах — закрыто в коде, ждёт server smoke

- **Исправлено:** общий fetcher переводит неуспешный HTTP-ответ в error-state, а не в ложный empty-state.
- **Проверка релиза:** 401, 403 и 5xx должны показывать понятное действие восстановления.

### H-02. Геометрия ключевых выдач при загрузке — закрыто в коде, ждёт server smoke

- **Исправлено:** выдачи используют стабилизированные skeleton/empty/error состояния и сохраняют размеры карточек.
- **Проверка релиза:** переключить фильтры на медленном соединении и убедиться в отсутствии заметного CLS.

### H-03. Загрузка фото при подаче транспорта — закрыто в коде, ждёт server smoke

- **Исправлено:** владелец добавляет, удаляет и упорядочивает фото до отправки формы; при отсутствии фото остаётся компактный честный placeholder.
- **Проверка релиза:** создать тестовый черновик с валидным изображением и убедиться, что обложка появляется в карточке.

### H-04. Светлая и тёмная темы пока мигрированы не полностью

- **Где:** большинство страниц и компонент используют жёсткие `#fff`, `#09090b`, `gray.*`, inline `style` и CSS-градиенты; в `globals.css` более 800 строк.
- **Проявление:** переключатель темы есть в header, но значительная часть поверхностей, текстов, footer и карточек не привязана к семантическим токенам и в тёмной теме может иметь неверный контраст.
- **Исправление:** в первой волне — базовые семантические tokens и глобальные focus/disabled стили; затем миграция страниц по приоритету, без одномоментного редизайна.

### H-05. Дублированные запросы избранного — закрыто в коде, ждёт server smoke

- **Исправлено:** набор избранного получает единый общий ключ и optimistic update для всех карточек.
- **Проверка релиза:** переключить избранное из сетки и из карточки объявления; состояние должно совпасть без перезагрузки.

### H-06. Базовые контроли — закрыто для каталога, запчастей и аукционов; остальные экраны требуют плановой миграции

- **Где:** карточки фильтров каталога уже частично стандартизированы, но запчасти, аукционы, формы публикации и кабинет применяют разные radius, border, размеры и inline стили.
- **Проявление:** на скриншотах фильтры сливаются, некоторые controls выглядят как текст, а не как интерактивные поля.
- **Исправление:** общие классы surface/field/action и доступные состояния focus/disabled; применять сначала к каталогам.

## Medium

### M-01. Непоследовательные empty/loading/error-состояния

- **Где:** сообщения, избранное, новости, аукционы, доставка, админка.
- **Проявление:** часть страниц имеет качественный empty-state, часть — только spinner или простой текст; явная error-подача почти отсутствует.
- **Исправление:** переиспользуемые `AsyncState`, `EmptyState`, skeleton, одна терминология и CTA.

### M-02. Изображения загружаются обычным `<img>` без единой политики размеров

- **Где:** карточки, детали, кабинет, аукционы, сравнение, карта.
- **Проявление:** риск CLS, отсутствие `sizes`/lazy-политики, неодинаковые fallback-сценарии и битые медиа.
- **Исправление:** сохранять фиксированное aspect-ratio, использовать `next/image` для предсказуемых и доверенных URL; оставить `<img>` только там, где он оправдан динамическим upload-preview.

### M-03. Слишком крупные клиентские компоненты

- **Где:** `HomeCatalog` (~32 KB), `VehicleDetailClient` (~34 KB), создание транспорта (~23 KB), доставка.
- **Проявление:** сложно менять без регрессий, растёт client bundle, тяжело тестировать независимые сценарии.
- **Исправление:** после стабилизации UX разделить на представление фильтров, секции характеристик, медиа и data hooks; использовать `useMemo` для derived data и не менять поведение API.

### M-04. Слабая типизация UI-ответов

- **Где:** многочисленные `any` в dashboard, compare, delivery, admin, listings.
- **Проявление:** несоответствие API и UI обнаруживается поздно, особенно для транспорта разных категорий.
- **Исправление:** интерфейсы/DTO в `src/lib`, type guards для JSON, постепенное снятие `any` с ключевых страниц.

### M-05. Навигация и footer требуют финальной продуктовой чистки

- **Где:** sidebar, header, footer.
- **Проявление:** основной UI уже убрал часть дублей, но footer повторяет разделы полностью; соцссылки пока ведут на `#`; контекст текущего раздела в header недостаточно выражен.
- **Исправление:** не добавлять дублирующие меню на ключевых разделах, отключить либо подключить реальные соцссылки, добавить понятные active-state и mobile проверку.

### M-06. Создание транспорта — длинная моноформa без прогресса

- **Где:** `listings/create/vehicle`.
- **Проявление:** на мобильном пользователю приходится проходить большой вертикальный список, обязательность и следующий шаг не видны до submit.
- **Исправление:** сохранить поля и API, но разделить форму на логические этапы/секции с прогрессом, inline validation и блоком фотографий.

## Low

### L-01. Inline стили мешают масштабировать дизайн-систему

- **Где:** десятки страниц и компонентов.
- **Исправление:** новые/изменяемые элементы строить на tokens/classes/Mantine styles; не выполнять рискованный массовый rewrite без визуального регрессионного набора.

### L-02. Есть технический Tailwind spinner рядом с Mantine

- **Где:** `src/components/ui/loading-spinner.tsx`.
- **Исправление:** либо привести к Mantine, либо удалить после проверки использования.

### L-03. Мобильные/keyboard сценарии нельзя полностью проверить без browser-run

- **Где:** menu, overlay, media gallery, filters, modals.
- **Исправление:** после восстановления browser connection пройти ручную матрицу 360/768/1024/1440px, клавиатуру и screen reader labels.

## Очередность исправлений

1. **Foundation:** error/not-found, typed fetcher, единые async states, focus/contrast tokens.
2. **Catalog core:** skeleton и error для транспорта/запчастей/аукционов, один store для избранного, предсказуемая media policy.
3. **Conversion:** фото в объявлении транспорта, более понятная форма размещения.
4. **Polish:** тёмная тема, footer/social links, page-specific responsive tuning, дробление крупных компонентов и удаление `any`.

## Критерии приёмки

- При 4xx/5xx пользователь видит понятную карточку ошибки и кнопку повтора, а не пустой каталог или техническую страницу.
- При загрузке сохраняется геометрия сетки; CLS на карточках отсутствует.
- Все новые поля/кнопки имеют label, доступный focus, disabled и loading состояния.
- Создание транспорта позволяет добавить до 12 фотографий, первая — обложка.
- Избранное делает один общий запрос на выдачу, а не запрос на каждую карточку.
- Каждая итерация проходит `tsc --noEmit`, `git diff --check`, commit/push и серверный build/deploy. Локальная production-сборка не выполняется.
