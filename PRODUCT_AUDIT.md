# Системный аудит «Авторынка»

Дата: 2026-08-09  
Основание: production HTTP/API, текущая схема Prisma, маршруты API, UI-код, предоставленный senior-аудит и предыдущий визуальный аудит. Встроенное browser-подключение в рабочем окружении недоступно, поэтому для интерактивной визуальной части требуется отдельный ручной прогон после восстановления соединения.

## Подтверждённое состояние

| Область | Факт | Оценка риска |
| --- | --- | --- |
| Public API | `/api/listings`, `/api/parts`, `/api/auctions`, models API отвечают `200` | низкий |
| Защищённые данные | `favorites`, dashboard и delivery для гостя отвечают `401` | низкий |
| Заголовки | CSP, `X-Frame-Options: DENY`, Referrer/Permissions Policy, COOP и CORP включены | низкий |
| Доставка | Есть заявки, события, документы, платежи и проверки прав | средний |
| Telegram | Есть webhook, привязка контакта и ограниченный по rate-limit OTP | средний |
| Избранное и async UI | Общий кэш, recovery/error/skeleton состояния добавлены | низкий |

## Critical — до запуска реальных сделок

### C-01. У объявления нет жизненного цикла, модерации и аудита

- **Наблюдение:** `Listing` хранит цену, промо и связи, но не имеет `status`, `publishedAt`, `moderatedAt`, `moderatedById`, причины отклонения или журнала действий.
- **Риск:** нельзя надёжно скрыть черновик, отправить на модерацию, снять сомнительное объявление, объяснить отклонение или восстановить историю решения.
- **Цель:** добавить статусную модель и неизменяемый audit trail из `LOGIC.md`; только активные объявления попадают в публичный каталог.

### C-02. Удаление объявления физическое

- **Наблюдение:** `DELETE /api/listings/[id]` вызывает `prisma.listing.delete`.
- **Риск:** теряется история, связь с сообщениями/жалобами/финансовыми следами и возможность восстановления ошибочного действия.
- **Цель:** заменить на soft-delete/archiving, хранить автора и время действия; физически удалять только по retention-политике.

### C-03. Нельзя назвать денежный сценарий «эскроу»

- **Наблюдение:** модель доставки корректно хранит счета, квитанции и подтверждение, но платёжный intent/webhook сам по себе не создаёт регулируемую escrow-сделку.
- **Риск:** пользователь может ошибочно поверить, что платформа держит деньги или гарантирует выкуп.
- **Цель:** до интеграции лицензированного провайдера использовать термин «сопровождаемая сделка»: отображать прямого получателя, счёт, квитанцию, ответственного и статус проверки. Слово «эскроу» — только после юридической и платёжной интеграции.

## High — P0 перед публичным запуском

### H-01. Роли и права представлены строками

- **Наблюдение:** `User.role` — свободная строка, а разрешения распределены по роутам.
- **Риск:** сложно доказывать и тестировать доступ к модерации, документам и сделкам; растёт риск регрессии при добавлении ролей партнёра/брокера.
- **Цель:** ввести enum ролей и централизованные policies: `USER`, `PARTNER`, `MODERATOR`, `ADMIN`; права проверять на ресурсе и действии.

### H-02. Production DB — SQLite

- **Наблюдение:** Prisma datasource использует SQLite.
- **Риск:** блокировки при параллельной записи, одиночная точка отказа, ограниченные бэкап/репликация/поиск для растущего классифайда.
- **Цель:** до реального трафика мигрировать на managed PostgreSQL, настроить ежедневные проверяемые бэкапы, мониторинг и восстановление.

### H-03. Схема Listing не обеспечивает целостность

- **Наблюдение:** комментарий в схеме прямо отмечает отсутствие ограничения «ровно один из vehicleId/partId».
- **Риск:** в БД может появиться некорректная полиморфная запись, которую UI не сможет отобразить.
- **Цель:** DB check constraint/migration и серверная валидация create/update; покрыть тестами.

### H-04. Слишком широкая политика remote images

- **Наблюдение:** `next.config.js` разрешает `https://**` для оптимизированных изображений.
- **Риск:** доверенный image proxy становится слишком широким каналом к сторонним источникам; сложнее контролировать стоимость, privacy и доступные домены.
- **Цель:** whitelist собственных storage/CDN и утверждённых источников аукционов; parser сохраняет нормализованные URL.

### H-05. UI ещё не премиален системно

- **Наблюдение:** уже есть tokens, общие async states и исправленные каталожные карточки, но крупные экраны содержат inline styles и крупные client components; адаптив не прошёл интерактивную матрицу.
- **Цель:** рефакторинг по экрану, а не массовая замена CSS: home → catalogue → detail → publish → account/mobile. Нужен визуальный baseline и ручной review на 360/768/1024/1440 px.

## Medium — после P0

- Полнотекстовый поиск запчастей пока не готов к PostgreSQL FTS/trigram и подбору всех кросс-номеров.
- Аукционам нужны живые импортированные фото/статусы и плановая очередь обновлений до заявок/сделок.
- Нет единого API DTO слоя: в ряде кабинетов и админки остаются `any`.
- `reactStrictMode` выключен; включать после устранения небезопасных side effects.
- Для HSTS нужен настоящий домен и HTTPS; на IP по HTTP включать его нельзя.

## Приоритет реализации

1. **Статусы, права и audit-log** без изменения публичного UX.
2. **Создание → модерация → публикация → снятие/продажа** с реальными API и кабинетами.
3. **Поиск/фильтры/карточка товара** с измеримым data contract.
4. **Аукцион → заявка → доставка** как прозрачное сопровождение, не фиктивный escrow.
5. **PostgreSQL, storage/CDN, observability, TLS/domain** до внешнего запуска.
